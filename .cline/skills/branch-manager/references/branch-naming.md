# branch-naming

## ブランチ命名規則

```
feature/<タスクNo>-<タスクのタイトル>
```

## 例

- `feature/FE002001-進捗表示 UI の実装`
- `feature/BE007001-FastAPI に CORS ミドルウェアを追加する`

## ブランチ運用手順

1. `git checkout main && git pull`
2. `git checkout -b feature/<タスクNo>-<タスクのタイトル>`
3. 作業実施
4. `git add -A && git commit -m "[<タスクNo>] <内容>"`
5. `git checkout main && git merge --no-ff feature/<タスクNo>-<タスクのタイトル>`

## コミット前必須チェック

- ユーザーによる動作テスト実施
- ユーザーからの「合格」明示的判定
- `<モジュール識別子>-TASKS.md` / `<モジュール識別子>-WORK-LOG.md` 更新内容のユーザー承認

## 禁止事項（Prohibited Operations）

- 既存の feature ブランチを強制上書き・再作成しない。同一タスク番号のブランチが存在する場合は既存ブランチを再利用するか、不要であれば削除してから新規作成する。
- 同じタスク番号で複数の feature ブランチを同時に作成・保持しない。
- `main` ブランチに直接コミットしない。すべてのタスク作業は feature ブランチ上で行う。
- マージ済みの feature ブランチをそのまま再利用しない。追加修正が必要な場合は新しいタスク番号を発行するか、明示的な理由をユーザーと確認する。
- 同名・同タスク番号のコミットを重複して作成しない。コミット前に `git log --oneline` で既存コミットを確認する。

## 例外：マージ済みブランチの再作成

`.clinerules` に「同一タスク番号のブランチを再作成しない」ルールがあるが、以下の場合は例外とする。

- **マージ済みタスクへの追加実装が必要になった場合**
  - 既に `main` にマージされたタスクに対し、UAT 中の新たな問題発見等で追加修正が必要になった場合
  - ブランチが削除済みであれば、同じタスク番号で新規作成する
  - ブランチが残存していれば、既存ブランチを再利用する
  - タスク管理表の完了日付が記入済みの場合は、追加実装前に完了日付を削除し、【実施結果】欄に追記する

本例外は、未マージの重複ブランチ作成を防ぐための禁止事項とは別の、マージ済みタスクのライフサイクル管理に関する規定である。
