# `<モジュール名>` タスク管理表

本ファイルは、`<モジュール名>` のタスクを追記型で管理するものです。
将来の課題も含め、すべて必ず実装することを前提としています。

## タスク粒度の方針

- タスクは数時間〜1日以内で完了できる粒度とする
- 1つのタスクに複数の責務が含まれる場合は分割を検討する
- 詳細項目を無理に別タスクにせず、達成可能な単位でまとめる
- 作業の記録はタスク詳細欄に箇条書きで記載する
- タスク No は「モジュール識別子（2文字）＋ ユースケースNo（3桁）＋ 通番（3桁）」とする
  - 識別子: `<識別子>`=`<モジュール名>`
  - 例：ユースケース001の1番目のタスク → `<識別子>001001`
- 通番は各ユースケース内で 001 から連番で振る

## タスク詳細欄の Markdown 記法ガイドライン

タスク詳細（`> 【計画】` / `> 【実施結果】` ブロック）では、コードフェンスや番号付き手順、入れ子見出しを含むことがあります。以下のルールに従って記述し、不要な `> - ` 付与を避けてください。

| 要素 | 正しい記法 | 誤りの例 |
|---|---|---|
| レコード形式の箇条書き（【実施結果】など） | `> - 2026-01-01: 実施内容` | — |
| 番号付き手順 | `> 1. 手順`<br>`> 2. 手順` | `> - 1. 手順` |
| 見出し | `> #### 1. 見出し` | `> - #### 1. 見出し` |
| 段落・説明文 | `> 本文テキスト` | `> - 本文テキスト` |
| 入れ子行（見出し・手順の子要素） | `>   子要素テキスト` | `> - - 子要素テキスト` |
| コードフェンス | `> \`\`\`language` | `> - \`\`\`language` |
| 【計画】・【実施結果】見出し | `> 【計画】` | `> - 【計画】` |

### 要点
- `> - ` は**真の箇条書きリスト**（実施結果の日付付きレコードなど）にのみ使用する
- 番号付きリスト、見出し、段落、コードフェンスには `> - ` を付けない
- 入れ子の内容は `>   `（`>` + 2 スペース）でインデントする
