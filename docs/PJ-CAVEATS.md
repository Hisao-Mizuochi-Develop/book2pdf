# PJ 注意事項・制約

本ファイルは、`PJ`（Project / プロジェクト運用・ガバナンス・ツール連携）に関する注意事項・制約・運用ルールを記載するものです。

---

## 1. 識別子の使い分け

- `PJ` は **プロジェクト運用・ガバナンス・外部ツール連携** に関する実装・整備・設定変更を対象とする
- `.clinerules` や AgentSkills の更新、JIRA / Confluence / Slack 等のツール連携設定変更は `PJ` とする
- ソースコード変更を伴わない純粋な文書整備（移動・整理・記録のみ）は `OT` とする（`.clinerules` 識別子選択基準 1 に従う）
- `docs/` 直下の新規仕様・設計文書の作成・変更は `SY` とする。ただし `.clinerules` / AgentSkills / 外部ツール連携に関する変更は `PJ` とする

## 2. タスク記録場所

- タスク管理: `docs/PJ-TASKS.md`
- 作業ログ: `docs/PJ-WORK-LOG.md`
- 注意事項: `docs/PJ-CAVEATS.md`（本ファイル）

## 3. 他モジュールとの関係

- `PJ` タスクは `.clinerules` や AgentSkills を変更するため、他モジュールのタスク実行にも影響を与える
- `.clinerules` / AgentSkills の変更を伴う `PJ` タスクは、Gate 3 でのユーザー承認が必須である
- `PJ` タスクによって導入された新ルールは、すべてのモジュール（`BE` / `FE` / `LA` / `OW`）のタスクにも適用される

## 4. ツール連携（プレースホルダー）

- `PJ002`（JIRA）、`PJ003`（Confluence）、`PJ004`（Slack）は将来の連携実装に備えたプレースホルダーである
- これらのツール連携に際しては、プロジェクトの機密情報（APIキー、トークン等）をコードやドキュメントに含めないこと
- 機密情報の管理方針は別途 `SY` または `PJ` タスクで策定する
