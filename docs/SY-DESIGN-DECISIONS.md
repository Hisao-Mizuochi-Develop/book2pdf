# 設計決定事項

本ドキュメントは、book2pdf プロジェクトの設計に関する決定事項をまとめたものです。

## 1. プロジェクト全体の方針

本プロジェクトは以下の2つのシステムから構成されます。

| システム | 用途 | 技術スタック |
|---|---|---|
| ローカルスタンドアローンアプリ | 電子書籍ページの画面キャプチャと外枠トリミング | Tauri v2 + Rust + React + Vite |
| Web システム | ZIP アーカイブに含まれるページ画像の OCR → 検索可能 PDF 生成 | Next.js 15 + FastAPI + Docker + ndlocr_cli |

Web システムの詳細な構成や実装計画は `backend/docs/backend-SY-WEB-OCR-SYSTEM-PLAN.md` を参照してください。

## 2. ローカルスタンドアローンアプリ

### 2.1 選定理由

- **クロスプラットフォーム対応**: macOS / Windows / Linux / iOS / Android（v2 から）に対応
- **モダン言語の習得**: Rust と TypeScript の両方を学べる
- **軽量**: Electron と比較してバイナリサイズが小さい
- **画面キャプチャ**: Tauri v2 の screenshot プラグインで対応可能

### 2.2 機能範囲

- 画面キャプチャ
- キャプチャ画像からの外枠不要部分のトリミング
- トリミング済み画像の保存

### 2.3 非機能要件

- OCR 機能は実装しない
- Web アーキテクチャは採用しない
- Docker コンテナは使用しない

## 3. Web システム

### 3.1 技術スタック

| レイヤー | 技術 |
|---|---|
| フロントエンド | Next.js 15（App Router）+ TypeScript + Tailwind CSS |
| バックエンド | FastAPI + Python |
| OCR エンジン | ndlocr_cli |
| PDF 生成 | PyMuPDF |
| ジョブ管理 | メモリ内（辞書） |
| 進捗通知 | Server-Sent Events (SSE) |
| コンテナ | Docker + Docker Compose |

コンテナ構成、処理フロー、PDF 仕様、OCR 実行形式などの詳細は `backend/docs/backend-SY-WEB-OCR-SYSTEM-PLAN.md` を参照してください。

## 4. 決定事項の変遷

### 4.1 日本語 OCR ライブラリの選定

当初は複数のライブラリを比較検討しましたが、縦書き・和書レイアウトに強い点から **ndlocr_cli** を選択しました。

検討候補:
- ndlocr_cli
- EasyOCR
- PaddleOCR
- MMOCR

除外:
- Tesseract（縦書きに弱いため）

### 4.2 実行環境

- **CPU 実行**: 高速処理を求めていないため、GPU は不要
- **Docker 化**: 自分で Dockerfile を組み立てる
- **コンテナ分離**: FastAPI と ndlocr_cli は別コンテナ

## 5. 将来の課題（次のステップで実装）

以下の項目は、現時点では採用しないが、将来の拡張として記録しておきます。

### 5.1 ジョブ状態の永続化

- **現状**: メモリ内（辞書）で管理
- **将来**: SQLite に永続化
- **理由**: プロセス再起動後もジョブ状態を保持し、複数 worker 間での状態共有を容易にするため

### 5.2 進捗通知方式

- **現状**: Server-Sent Events (SSE)
- **将来**: フロントエンドのポーリング
- **理由**: 環境によってはプロキシやタイムアウトで SSE が不安定になる場合があるため、フォールバック手段として検討

## 6. 注意事項

- 既存の `old/` ディレクトリ内のアプリケーションは仕様のみ参考とし、ソースコード・ドキュメントは直接流用しない
- Kindle 等の電子書籍コンテンツのキャプチャは、著作権・利用規約の範囲内で行うこと
- DRM 保護されたコンテンツの自動取得は行わない
