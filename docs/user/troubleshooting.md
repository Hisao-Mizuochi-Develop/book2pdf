# トラブルシューティングFAQ

macOS移植・動作検証の過程で実際に発生した不具合とその対処法をまとめています。

## キャプチャがKindleではなくデスクトップ/別のウィンドウを撮ってしまう

考えられる原因は3つあります。いずれも kindle2pdf 側で検出・防止する仕組みを
入れていますが、根本対処は以下の通りです。

1. **画面収録権限が未許可** — [permissions.md](permissions.md) を確認してください。
   権限がないと `screencapture` が壁紙相当の画像しか返さないことがあります。
2. **対象ウィンドウが最前面になっていない** — キャプチャ開始前・キャプチャ中に
   継続してチェックしており、最前面でなければ明確なエラーで停止します
   （「対象ウィンドウを前面にできませんでした」等）。電子書籍アプリを操作中に
   他のウィンドウをクリックしないでください。
3. **Macがスリープ/画面ロックした** — 長時間のキャプチャでアイドルタイムアウトに
   より画面がロックされると、当然ながら操作できなくなります。システム設定の
   ロック画面設定でスリープまでの時間を延ばしてください。

## ページがめくれず、同じ1ページ目を撮り続ける

主な原因は次のいずれかです。

1. **アクセシビリティ権限が未許可** — [permissions.md](permissions.md)。
   権限がないとキー送信が例外なく黙って失敗するため、最も見つけにくい原因です。
   起動時のチェックでエラー表示されるようになっているので、まずそこを確認してください。
2. **ページめくりキーがそのアプリ/表示モードに合っていない** — 例えば
   ページめくり表示ではなく連続スクロール表示になっていると、矢印キーが
   効かないことがあります。kindle2pdf はこの対策として、ページが変化しない場合
   自動的に次の方式へエスカレーションします。

   ```
   矢印キー(既定) → スペース → PageDown → 下矢印 → マウスホイールスクロール
   ```

   一度有効な方式が見つかると、以降のページもその方式が使われ続けます
   （`core/capture_engine.py` の `_page_turn_methods()` / `_send_page_turn()`）。
3. **カーソル点滅などのノイズを「ページ変化」と誤検出していた（過去の不具合、対策済み）** —
   以前は1ピクセルでも差分があれば「変化した」と判定していたため、点滅カーソルなどの
   微小なノイズでも次ページに進んだと誤認識し、実質同じ1ページ目の画像を
   ファイル名だけ変えて量産する不具合がありました。現在は差分ピクセル数が
   全体の0.5%を超えない限り「変化なし」とみなす閾値判定（`_has_meaningful_change()`）
   を入れて解消しています。

## 「ウィンドウが見つかりません」と出る

- 対象アプリが**起動されているか**確認してください
- ウィンドウが**最小化されていないか**確認してください（フルスクリーンでも
  「見えている」扱いにはなりますが、別のSpaceに切り替わっている場合は
  最前面化に失敗することがあります）
- 詳細設定の「ウィンドウタイトル」「プロセス名」が実際のアプリと一致しているか確認してください
  ([custom-profiles.md](custom-profiles.md) のプロセス名一覧の取得方法を参照)
- プロセス名を指定している場合、そのプロセス名のウィンドウが1つも見つからなければ
  意図的に `None`（見つからない）を返す仕様です。これは無関係なウィンドウを
  誤って掴む事故を防ぐためで、必要なら詳細設定でプロセス名欄を空にしてください。

## ウィンドウが勝手にフルスクリーンになる／消える（過去の不具合、対策済み）

macOSのウィンドウは左上に「閉じる/しまう/フルスクリーン」ボタン（信号機ボタン）が
あります。過去バージョンでは、ウィンドウを前面化する際のクリック位置がこのボタンに
重なっており、誤って緑の「フルスクリーン化」ボタンを押してしまい、対象アプリが
独立したSpaceに切り替わってウィンドウが見失われる不具合がありました。

現在は、macOS版の `activate_window()` はウィンドウ内をクリックしません
（`NSRunningApplication.activateWithOptions_` によるアプリ全体のアクティブ化だけで
キーボードフォーカスの切り替えには十分なため）。もし同様の症状が再発した場合は、
`core/window_utils.py` の `activate_window()` にクリック処理が復活していないか確認してください。

## OCRエンジンが「見つかりません」と表示される

`ndlocr-lite` フォルダが `kindle2pdf_mac/ndlocr-lite/` に正しく配置されているか
確認してください。[setup.md](setup.md) の手順3を参照してください。
画像PDFの変換はOCR不要なので、NDLOCR-Liteなしでも使えます。

## トリミングの余白をどう決めればいい？

トリミングタブの「自動検出」ボタンで概算値を入れたあと、プレビューを見ながら
微調整するのがおすすめです。自動検出はやや余裕を持たせた値（コンテンツを
切り落とさない方向）を返すので、そこから値を増やして寄せていってください。
