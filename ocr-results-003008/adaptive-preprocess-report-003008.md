# 対象ページに応じた適応的前処理の検討レポート（タスク 003008）

## 概要

| 項目 | 内容 |
|---|---|
| タスク No | 003008 |
| タスク名 | 対象ページに応じた適応的前処理の検討 |
| 実施日 | 2026-09-01 |
| タスク種別 | 要検討対応 |
| 目的 | ページタイプ別（表紙/目次/本文）に最適な前処理パラメータを切り替える方式の実現可能性を調査・判断する |
| 情報源 | 003003・003004・003007 の過去検証結果、003003/003007 のワークログ |

## 背景

003003 および 003007 の検証結果より、入力画像に対する一律の前処理では、全ページタイプ（表紙・目次・本文）で最適な認識精度が得られるとは限らないことが示唆された。

特に以下の傾向が確認された：

- `sharpen_light_upscale_2x`（2 倍アップスケール＋軽度シャープニング）は本文ページで高い効果を示した
- `local_binarization` は「〓」未認識記号の出現数を減らす傾向があったが、文字潰れによる誤認識が増加した
- 表紙ページは特殊なフォント・レイアウト・デザインの影響から、どの前処理パターンを適用しても一部の誤認識が残存した

このため、ページタイプに応じて前処理パラメータを切り替える「適応的前処理」の導入が議論された。

## 検討方式と評価

### 方式 1：ページ分類ベース

**アプローチ**
- 文字サイズ分布・色数・エッジ密度・画像統計量などの特徴量から、ページを「表紙/目次/本文/その他」に自動分類する
- 分類結果に応じて前処理パターンを切り替える

**評価**
| 観点 | 評価 |
|---|---|
| 実装コスト | 高い。分類器の学習用データ収集・ラベル付け・検証が必要 |
| 処理時間 | 分類処理の追加により、1 ページあたり数秒〜数十秒の増加が見込まれる |
| 期待効果 | 中程度。表紙・目次・本文の特徴が明確であれば効果を発揮する可能性がある |
| 技術的リスク | 分類ミスが発生した場合、逆に精度が低下する可能性がある |

**結論**: 現時点ではコストに見合った効果が不明確。

### 方式 2：認識置信度ベース

**アプローチ**
- 標準前処理（`sharpen_light_upscale_2x`）適用後の OCR 結果から、CONF 値や「〓」出現率を抽出する
- 置信度が低いページや「〓」が多いページに対して、別の前処理パターン（例：`local_binarization`）を適用して再 OCR する

**評価**
| 観点 | 評価 |
|---|---|
| 実装コスト | 中程度。再 OCR フローと結果の選別ロジックが必要 |
| 処理時間 | 2 パス化するため、処理時間が約 2 倍になる可能性がある |
| 期待効果 | 中程度。再 OCR により部分的な改善が期待できる |
| 技術的リスク | 第 1 パスと第 2 パスの結果をどのように統合するかが難しい。最悪の結果を選んでしまうリスクもある |

**結論**: 処理時間増加と実装複雑化の割に、改善効果が限定的な可能性がある。

### 方式 3：レイアウト認識結果ベース

**アプローチ**
- ndlocr_cli の出力である TEXTBLOCK 数・領域サイズ分布・文字行の配置から、特殊ページ（表紙・目次・図版ページなど）を検出する
- 検出結果に応じて前処理パラメータを切り替える

**評価**
| 観点 | 評価 |
|---|---|
| 実装コスト | 中〜高。ndlocr_cli の中間出力（XML）を解析し、信頼性のある判定基準を設定する必要がある |
| 処理時間 | 1 パス目のレイアウト認識結果を利用するため、追加時間は比較的少ない可能性がある |
| 期待効果 | 中程度。目次や図版ページの検出には有効かもしれない |
| 技術的リスク | ndlocr_cli のバージョンアップで XML 形式が変わると連携が破損するリスクがある |

**結論**: 実装コストと保守性のバランスが悪い。

## 定量的根拠

### 003003 の結果（3 ページ、各前処理パターン比較）

| パターン | 「〓」出現数 |
|---|---|
| baseline（前処理なし） | 5 |
| sharpen_light | 7 |
| **sharpen_light_upscale_2x** | **3** |
| contrast_gamma | 7 |
| contrast_gamma_sharpen_light | 6 |

### 003007 の結果（10 ページ、追加前処理比較）

| パターン | 「〓」出現数（total） | 傾向 |
|---|---|---|
| baseline_2x | 194 | 現状の基準 |
| 4x_upscale | 202 | baseline より悪化、ファイルサイズ 279MB と 3 倍以上 |
| 4x_upscale_sharpen | 178 | baseline より改善だが、コストに見合わず |
| local_binarization | 135 | 「〓」数は最少だが文字潰れによる誤認識が多い |
| local_binarization_sharpen | 135 | local_binarization と同様 |
| contrast_strong | 160 | 一部ページで認識欠落あり |
| contrast_strong_4x | 176 | baseline 並み |

### 観察された傾向

- `sharpen_light_upscale_2x` は比較的安定して効果を示した
- `local_binarization` は「〓」数を減らすが、文字潰れによる別の誤認識を招く
- 表紙ページは特殊フォント・デザインのため、どの前処理を適用しても完全な認識は困難だった
- 技術書の場合、表紙は 1 ページのみであり、目次も数ページ程度に限定される

## 結論

**現時点では、対象ページに応じた適応的前処理の導入は保留とする。**

理由は以下の通り：

1. **コストパフォーマンスが不明確**: ページ分類器の実装・学習・保守コストに対し、得られる精度向上が限定的である可能性が高い
2. **処理時間の増加**: 再 OCR や分類処理の追加により、既に 1 ページあたり約 125 秒かかる処理時間がさらに増加する
3. **技術書の構成特性**: 表紙は 1 ページ、目次も少数ページであり、一律前処理を維持する方がシンプルで信頼性が高い
4. **代替策の存在**: 適応的前処理よりも、OCR 後処理（辞書補正・正規表現による修正）や UI での手動補正を優先することで、より高いコストパフォーマンスが期待できる

## 今後の検討事項

- 将来的に対象ドキュメントが雑誌・論文集・表紙・目次が多数含まれるものに変わる場合は、再検討する
- 認識置信度ベースの方式について、軽量なプロトタイプで効果検証を行う価値がある
- ndlocr_cli の将来バージョンでレイアウト情報がより充実した場合、方式 3 の再検討も検討する
- 当面は 003003/003006 で採用された `sharpen_light_upscale_2x` 前処理を標準として維持する
