32/// Specifies which compression method to use.
33///
34/// Use uncompressed data for fastest loading and writing speeds.
35/// Use RLE compression for fast loading and writing with slight memory savings.
36/// Use ZIP compression for slow processing with large memory savings.
37#[derive(Debug, Clone, Copy, PartialEq)]
38pub enum Compression {
39    /// Store uncompressed values.
40    /// Produces large files that can be read and written very quickly.
41    /// Consider using RLE instead, as it provides some compression with almost
42    /// equivalent speed.
43    Uncompressed,
44
45    /// Produces slightly smaller files
46    /// that can still be read and written rather quickly.
47    /// The compressed file size is usually between 60 and 75 percent of the
48    /// uncompressed size. Works best for images with large flat areas, such
49    /// as masks and abstract graphics. This compression method is lossless.
50    RLE,
51
52    /// Uses ZIP compression to compress each line. Slowly produces small images
53    /// which can be read with moderate speed. This compression method is
54    /// lossless. Might be slightly faster but larger than `ZIP16´.
55    ZIP1, /* TODO ZIP { individual_lines: bool, compression_level: Option<u8> }  // TODO
56           * specify zip compression level? */
57    /// Uses ZIP compression to compress blocks of 16 lines. Slowly produces
58    /// small images which can be read with moderate speed. This compression
59    /// method is lossless. Might be slightly slower but smaller than
60    /// `ZIP1´.
61    ZIP16, // TODO collapse with ZIP1
62
63    /// PIZ compression works well for noisy and natural images. Works better
64    /// with larger tiles. Only supported for flat images, but not for deep
65    /// data. This compression method is lossless.
66    // A wavelet transform is applied to the pixel data, and the result is Huffman-
67    // encoded. This scheme tends to provide the best compression ratio for the types of
68    // images that are typically processed at Industrial Light & Magic. Files are
69    // compressed and decompressed at roughly the same speed. For photographic
70    // images with film grain, the files are reduced to between 35 and 55 percent of their
71    // uncompressed size.
72    // PIZ compression works well for scan-line based files, and also for tiled files with
73    // large tiles, but small tiles do not shrink much. (PIZ-compressed data start with a
74    // relatively long header; if the input to the compressor is short, adding the header
75    // tends to offset any size reduction of the input.)
76    PIZ,
77
78    /// Like `ZIP1`, but reduces precision of `f32` images to `f24`.
79    /// Therefore, this is lossless compression for `f16` and `u32` data, lossy
80    /// compression for `f32` data. This compression method works well for
81    /// depth buffers and similar images, where the possible range of values
82    /// is very large, but where full 32-bit floating-point accuracy is not
83    /// necessary. Rounding improves compression significantly by
84    /// eliminating the pixels' 8 least significant bits, which tend to be
85    /// very noisy, and therefore difficult to compress. This produces
86    /// really small image files. Only supported for flat images, not for deep
87    /// data.
88    // After reducing 32-bit floating-point data to 24 bits by rounding (while leaving 16-bit
89    // floating-point data unchanged), differences between horizontally adjacent pixels
90    // are compressed with zlib, similar to ZIP. PXR24 compression preserves image
91    // channels of type HALF and UINT exactly, but the relative error of FLOAT data
92    // increases to about ???.
93    PXR24, // TODO specify zip compression level?
94
95    /// This is a lossy compression method for f16 images.
96    /// It's the predecessor of the `B44A` compression,
97    /// which has improved compression rates for uniformly colored areas.
98    /// You should probably use `B44A` instead of the plain `B44`.
99    ///
100    /// Only supported for flat images, not for deep data.
101    // lossy 4-by-4 pixel block compression,
102    // flat fields are compressed more
103    // Channels of type HALF are split into blocks of four by four pixels or 32 bytes. Each
104    // block is then packed into 14 bytes, reducing the data to 44 percent of their
105    // uncompressed size. When B44 compression is applied to RGB images in
106    // combination with luminance/chroma encoding (see below), the size of the
107    // compressed pixels is about 22 percent of the size of the original RGB data.
108    // Channels of type UINT or FLOAT are not compressed.
109    // Decoding is fast enough to allow real-time playback of B44-compressed OpenEXR
110    // image sequences on commodity hardware.
111    // The size of a B44-compressed file depends on the number of pixels in the image,
112    // but not on the data in the pixels. All images with the same resolution and the same
113    // set of channels have the same size. This can be advantageous for systems that
114    // support real-time playback of image sequences; the predictable file size makes it
115    // easier to allocate space on storage media efficiently.
116    // B44 compression is only supported for flat images.
117    B44, // TODO B44 { optimize_uniform_areas: bool }
118
119    /// This is a lossy compression method for f16 images.
120    /// All f32 and u32 channels will be stored without compression.
121    /// All the f16 pixels are divided into 4x4 blocks.
122    /// Each block is then compressed as a whole.
123    ///
124    /// The 32 bytes of a block will require only ~14 bytes after compression,
125    /// independent of the actual pixel contents. With chroma subsampling,
126    /// a block will be compressed to ~7 bytes.
127    /// Uniformly colored blocks will be compressed to ~3 bytes.
128    ///
129    /// The 512 bytes of an f32 block will not be compressed at all.
130    ///
131    /// Should be fast enough for realtime playback.
132    /// Only supported for flat images, not for deep data.
133    B44A, // TODO collapse with B44
134
135    /// Lossy DCT-based compression (DreamWorks Animation), 32 scanlines per
136    /// block. Partial buffer access friendly.
137    /// Decoding support is implemented. Encoding is not implemented and returns
138    /// an error.
139    DWAA(Option<f32>),
140
141    /// Lossy DCT-based compression (DreamWorks Animation), 256 scanlines per
142    /// block. Better compression ratio for full frames.
143    /// Decoding support is implemented. Encoding is not implemented and returns
144    /// an error.
145    DWAB(Option<f32>),
146
147    /// __This lossy compression is not yet supported by this implementation.__
148    // High-Throughput JPEG 2000 (32 lines)
149    HTJ2K32,
150
151    /// __This lossy compression is not yet supported by this implementation.__
152    // High-Throughput JPEG 2000 (256 lines)
153    HTJ2K256,
154}

180    /// Compress the image section, converting from native endian into with
181    /// little-endian format.
182    pub fn compress_image_section_to_le(
183        self,
184        header: &Header,
185        uncompressed_native_endian: ByteVec,
186        pixel_section: IntegerBounds,
187    ) -> Result<ByteVec> {
188        let max_tile_size = header.max_block_pixel_size();
189
190        assert!(
191            pixel_section.validate(Some(max_tile_size)).is_ok(),
192            "decompress tile coordinate bug"
193        );
194        if header.deep {
195            assert!(self.supports_deep_data());
196        }
197
198        use self::Compression::*;
199        let compressed_little_endian = match self {
200            Uncompressed => {
201                return convert_current_to_little_endian(
202                    uncompressed_native_endian,
203                    &header.channels,
204                    pixel_section,
205                );
206            }
207
208            // we need to clone here, because we might have to fallback to the uncompressed data
209            // later (when compressed data is larger than raw data)
210            ZIP16 => zip::compress_bytes(
211                &header.channels,
212                uncompressed_native_endian.clone(),
213                pixel_section,
214            ),
215            ZIP1 => zip::compress_bytes(
216                &header.channels,
217                uncompressed_native_endian.clone(),
218                pixel_section,
219            ),
220            RLE => rle::compress_bytes(
221                &header.channels,
222                uncompressed_native_endian.clone(),
223                pixel_section,
224            ),
225            PIZ => {
226                piz::compress(&header.channels, uncompressed_native_endian.clone(), pixel_section)
227            }
228            PXR24 => {
229                pxr24::compress(&header.channels, uncompressed_native_endian.clone(), pixel_section)
230            }
231            B44 => b44::compress(
232                &header.channels,
233                uncompressed_native_endian.clone(),
234                pixel_section,
235                false,
236            ),
237            B44A => b44::compress(
238                &header.channels,
239                uncompressed_native_endian.clone(),
240                pixel_section,
241                true,
242            ),
243            DWAA(level) | DWAB(level) => dwa::compress(
244                &header.channels,
245                uncompressed_native_endian.clone(),
246                pixel_section,
247                level,
248            ),
249            _ => {
250                return Err(Error::unsupported(format!(
251                    "yet unimplemented compression method: {self}"
252                )));
253            }
254        };
255
256        let compressed_little_endian = compressed_little_endian
257            .map_err(|_| Error::invalid(format!("pixels cannot be compressed ({self})")))?;
258
259        if self == Uncompressed || compressed_little_endian.len() < uncompressed_native_endian.len()
260        {
261            // only write compressed if it actually is smaller than raw
262            Ok(compressed_little_endian)
263        } else {
264            // if we do not use compression, manually convert uncompressed data
265            convert_current_to_little_endian(
266                uncompressed_native_endian,
267                &header.channels,
268                pixel_section,
269            )
270        }
271    }

273    /// Decompress the image section from bytes of little-endian format,
274    /// returning native-endian format.
275    pub fn decompress_image_section_from_le(
276        self,
277        header: &Header,
278        compressed_le: ByteVec,
279        pixel_section: IntegerBounds,
280        pedantic: bool,
281    ) -> Result<ByteVec> {
282        let max_tile_size = header.max_block_pixel_size();
283
284        assert!(
285            pixel_section.validate(Some(max_tile_size)).is_ok(),
286            "decompress tile coordinate bug"
287        );
288        if header.deep {
289            assert!(self.supports_deep_data());
290        }
291
292        let expected_byte_size = pixel_section.size.area() * header.channels.bytes_per_pixel; // FIXME this needs to account for subsampling anywhere
293
294        // note: always true where self == Uncompressed
295        if compressed_le.len() == expected_byte_size {
296            // the compressed data was larger than the raw data, so the small raw data has
297            // been written
298            convert_little_endian_to_current(compressed_le, &header.channels, pixel_section)
299        } else {
300            use self::Compression::*;
301            let bytes_ne = match self {
302                Uncompressed => {
303                    convert_little_endian_to_current(compressed_le, &header.channels, pixel_section)
304                }
305                ZIP16 => zip::decompress_bytes(
306                    &header.channels,
307                    compressed_le,
308                    pixel_section,
309                    expected_byte_size,
310                    pedantic,
311                ),
312                ZIP1 => zip::decompress_bytes(
313                    &header.channels,
314                    compressed_le,
315                    pixel_section,
316                    expected_byte_size,
317                    pedantic,
318                ),
319                RLE => rle::decompress_bytes(
320                    &header.channels,
321                    compressed_le,
322                    pixel_section,
323                    expected_byte_size,
324                    pedantic,
325                ),
326                PIZ => piz::decompress(
327                    &header.channels,
328                    compressed_le,
329                    pixel_section,
330                    expected_byte_size,
331                    pedantic,
332                ),
333                PXR24 => pxr24::decompress(
334                    &header.channels,
335                    compressed_le,
336                    pixel_section,
337                    expected_byte_size,
338                    pedantic,
339                ),
340                B44 | B44A => b44::decompress(
341                    &header.channels,
342                    compressed_le,
343                    pixel_section,
344                    expected_byte_size,
345                    pedantic,
346                ),
347                DWAA(_) | DWAB(_) => dwa::decompress(
348                    &header.channels,
349                    compressed_le,
350                    pixel_section,
351                    expected_byte_size,
352                    pedantic,
353                ),
354                _ => {
355                    return Err(Error::unsupported(format!(
356                        "yet unimplemented compression method: {self}"
357                    )));
358                }
359            };
360
361            // map all errors to compression errors
362            let bytes_ne = bytes_ne.map_err(|decompression_error| match decompression_error {
363                Error::NotSupported(message) => Error::unsupported(format!(
364                    "yet unimplemented compression special case ({message})"
365                )),
366
367                error => Error::invalid(format!("compressed {self:?} data ({error})")),
368            })?;
369
370            if bytes_ne.len() == expected_byte_size {
371                Ok(bytes_ne)
372            } else {
373                Err(Error::invalid("decompressed data"))
374            }
375        }
376    }

401    /// Most compression methods will reconstruct the exact pixel bytes,
402    /// but some might throw away unimportant data for specific types of
403    /// samples.
404    pub fn is_lossless_for(self, sample_type: SampleType) -> bool {
405        use self::Compression::*;
406        match self {
407            PXR24 => sample_type != SampleType::F32, // pxr reduces f32 to f24
408            // B44 only compresses f16 values; other sample types are left
409            // uncompressed.
410            B44 | B44A => sample_type != SampleType::F16,
411            Uncompressed | RLE | ZIP1 | ZIP16 | PIZ | HTJ2K32 | HTJ2K256 => true,
412            DWAB(_) | DWAA(_) => false,
413        }
414    }

453#[allow(unused)] // allows the extra parameters to be unused
454fn convert_current_to_little_endian(
455    mut bytes: ByteVec,
456    channels: &ChannelList,
457    rectangle: IntegerBounds,
458) -> Result<ByteVec> {
459    #[cfg(target_endian = "big")]
460    reverse_block_endianness(&mut bytes, channels, rectangle)?;
461
462    Ok(bytes)
463}

477#[allow(unused)] // unused when on little endian system
478fn reverse_block_endianness(
479    bytes: &mut [u8],
480    channels: &ChannelList,
481    rectangle: IntegerBounds,
482) -> UnitResult {
483    let mut remaining_bytes: &mut [u8] = bytes;
484
485    for y in rectangle.position.y()..rectangle.end().y() {
486        for channel in &channels.list {
487            let line_is_subsampled = mod_p(y, usize_to_i32(channel.sampling.y(), "sampling")?) != 0;
488            if line_is_subsampled {
489                continue;
490            }
491
492            let sample_count = rectangle.size.width() / channel.sampling.x();
493
494            match channel.sample_type {
495                SampleType::F16 => {
496                    remaining_bytes =
497                        convert_byte_chunks(reverse_2_bytes, 2, remaining_bytes, sample_count);
498                }
499
500                SampleType::F32 => {
501                    remaining_bytes =
502                        convert_byte_chunks(reverse_4_bytes, 4, remaining_bytes, sample_count);
503                }
504
505                SampleType::U32 => {
506                    remaining_bytes =
507                        convert_byte_chunks(reverse_4_bytes, 4, remaining_bytes, sample_count);
508                }
509            }
510        }
511    }
512
513    // Converts groups of bytes (e.g. 2 bytes), as many groups as specified. Returns
514    // a slice of the remaining bytes.
515    #[inline]
516    fn convert_byte_chunks(
517        convert_single_value: fn(&mut [u8]),
518        batch_size: usize,
519        bytes: &mut [u8],
520        batch_count: usize,
521    ) -> &mut [u8] {
522        let (line_bytes, rest) = bytes.split_at_mut(batch_count * batch_size);
523        let value_byte_chunks = line_bytes.chunks_exact_mut(batch_size);
524
525        for value_bytes in value_byte_chunks {
526            convert_single_value(value_bytes);
527        }
528
529        rest
530    }
531
532    debug_assert!(remaining_bytes.is_empty(), "not all bytes were converted to little endian");
533    Ok(())
534}

536#[inline]
537fn reverse_2_bytes(bytes: &mut [u8]) {
538    // this code seems like it could be optimized easily by the compiler
539    let two_bytes: [u8; 2] = bytes.try_into().expect("invalid byte count");
540    bytes.copy_from_slice(&[two_bytes[1], two_bytes[0]]);
541}
542
543#[inline]
544fn reverse_4_bytes(bytes: &mut [u8]) {
545    let four_bytes: [u8; 4] = bytes.try_into().expect("invalid byte count");
546    bytes.copy_from_slice(&[four_bytes[3], four_bytes[2], four_bytes[1], four_bytes[0]]);
547}

549#[inline]
550const fn div_p(x: i32, y: i32) -> i32 {
551    if x >= 0 {
552        if y >= 0 {
553            x / y
554        } else {
555            -(x / -y)
556        }
557    } else if y >= 0 {
558        -((y - 1 - x) / y)
559    } else {
560        (-y - 1 - x) / -y
561    }
562}
563
564#[inline]
565const fn mod_p(x: i32, y: i32) -> i32 {
566    x - y * div_p(x, y)
567}

569/// A collection of functions used to prepare data for compression.
570mod optimize_bytes {
571    /// Integrate over all differences to the previous value in order to
572    /// reconstruct sample values.
573    pub fn differences_to_samples(buffer: &mut [u8]) {
574        // The naive implementation is very simple:
575        //
576        // for index in 1..buffer.len() {
577        //    buffer[index] = (buffer[index - 1] as i32 + buffer[index] as i32 - 128) as
578        // u8; }
579        //
580        // But we process elements in pairs to take advantage of instruction-level
581        // parallelism. When computations within a pair do not depend on each
582        // other, they can be processed in parallel. Since this function is
583        // responsible for a very large chunk of execution time, this tweak
584        // alone improves decoding performance of RLE images by 20%.
585        if let Some(first) = buffer.first() {
586            let mut previous = i16::from(*first);
587            for chunk in &mut buffer[1..].chunks_exact_mut(2) {
588                // no bounds checks here due to indices and chunk size being constant
589                let diff0 = i16::from(chunk[0]);
590                let diff1 = i16::from(chunk[1]);
591                // these two computations do not depend on each other, unlike in the naive
592                // version, so they can be executed by the CPU in parallel via
593                // instruction-level parallelism
594                let sample0 = (previous + diff0 - 128) as u8;
595                let sample1 = (previous + diff0 + diff1 - 128 * 2) as u8;
596                chunk[0] = sample0;
597                chunk[1] = sample1;
598                previous = i16::from(sample1);
599            }
600            // handle the remaining element at the end not processed by the loop over pairs,
601            // if present
602            for elem in &mut buffer[1..].chunks_exact_mut(2).into_remainder().iter_mut() {
603                let sample = (previous + i16::from(*elem) - 128) as u8;
604                *elem = sample;
605                previous = i16::from(sample);
606            }
607        }
608    }

610    /// Derive over all values in order to produce differences to the previous
611    /// value.
612    pub fn samples_to_differences(buffer: &mut [u8]) {
613        // naive version:
614        // for index in (1..buffer.len()).rev() {
615        //     buffer[index] = (buffer[index] as i32 - buffer[index - 1] as i32 + 128)
616        // as u8; }
617        //
618        // But we process elements in batches to take advantage of autovectorization.
619        // If the target platform has no vector instructions (e.g. 32-bit ARM without
620        // `-C target-cpu=native`) this will instead take advantage of
621        // instruction-level parallelism.
622        if let Some(first) = buffer.first() {
623            let mut previous = i16::from(*first);
624            // Chunk size is 16 because we process bytes (8 bits),
625            // and 8*16 = 128 bits is the size of a typical SIMD register.
626            // Even WASM has 128-bit SIMD registers.
627            for chunk in &mut buffer[1..].chunks_exact_mut(16) {
628                // no bounds checks here due to indices and chunk size being constant
629                let sample0 = i16::from(chunk[0]);
630                let sample1 = i16::from(chunk[1]);
631                let sample2 = i16::from(chunk[2]);
632                let sample3 = i16::from(chunk[3]);
633                let sample4 = i16::from(chunk[4]);
634                let sample5 = i16::from(chunk[5]);
635                let sample6 = i16::from(chunk[6]);
636                let sample7 = i16::from(chunk[7]);
637                let sample8 = i16::from(chunk[8]);
638                let sample9 = i16::from(chunk[9]);
639                let sample10 = i16::from(chunk[10]);
640                let sample11 = i16::from(chunk[11]);
641                let sample12 = i16::from(chunk[12]);
642                let sample13 = i16::from(chunk[13]);
643                let sample14 = i16::from(chunk[14]);
644                let sample15 = i16::from(chunk[15]);
645                // Unlike in decoding, computations in here are truly independent from each
646                // other, which enables the compiler to vectorize this loop.
647                // Even if the target platform has no vector instructions,
648                // so using more parallelism doesn't imply doing more work,
649                // and we're not really limited in how wide we can go.
650                chunk[0] = (sample0 - previous + 128) as u8;
651                chunk[1] = (sample1 - sample0 + 128) as u8;
652                chunk[2] = (sample2 - sample1 + 128) as u8;
653                chunk[3] = (sample3 - sample2 + 128) as u8;
654                chunk[4] = (sample4 - sample3 + 128) as u8;
655                chunk[5] = (sample5 - sample4 + 128) as u8;
656                chunk[6] = (sample6 - sample5 + 128) as u8;
657                chunk[7] = (sample7 - sample6 + 128) as u8;
658                chunk[8] = (sample8 - sample7 + 128) as u8;
659                chunk[9] = (sample9 - sample8 + 128) as u8;
660                chunk[10] = (sample10 - sample9 + 128) as u8;
661                chunk[11] = (sample11 - sample10 + 128) as u8;
662                chunk[12] = (sample12 - sample11 + 128) as u8;
663                chunk[13] = (sample13 - sample12 + 128) as u8;
664                chunk[14] = (sample14 - sample13 + 128) as u8;
665                chunk[15] = (sample15 - sample14 + 128) as u8;
666                previous = sample15;
667            }
668            // Handle the remaining element at the end not processed by the loop over
669            // batches, if present This is what the iterator-based version of
670            // this function would look like without vectorization
671            for elem in &mut buffer[1..].chunks_exact_mut(16).into_remainder().iter_mut() {
672                let diff = (i16::from(*elem) - previous + 128) as u8;
673                previous = i16::from(*elem);
674                *elem = diff;
675            }
676        }
677    }

679    use std::cell::Cell;
680    thread_local! {
681        // A buffer for reusing between invocations of interleaving and deinterleaving.
682        // Allocating memory is cheap, but zeroing or otherwise initializing it is not.
683        // Doing it hundreds of times (once per block) would be expensive.
684        // This optimization brings down the time spent in interleaving from 15% to 5%.
685        static SCRATCH_SPACE: Cell<Vec<u8>> = const { Cell::new(Vec::new()) };
686    }
687
688    fn with_reused_buffer<F>(length: usize, mut func: F)
689    where
690        F: FnMut(&mut [u8]),
691    {
692        SCRATCH_SPACE.with(|scratch_space| {
693            // reuse a buffer if we've already initialized one
694            let mut buffer = scratch_space.take();
695            if buffer.len() < length {
696                // Efficiently create a zeroed Vec by requesting zeroed memory from the OS.
697                // This is slightly faster than a `memcpy()` plus `memset()` that would happen
698                // otherwise, but is not a big deal either way since it's not a
699                // hot codepath.
700                buffer = vec![0u8; length];
701            }
702
703            // call the function
704            func(&mut buffer[..length]);
705
706            // save the internal buffer for reuse
707            scratch_space.set(buffer);
708        });
709    }
710
711    /// Interleave the bytes such that the second half of the array is every
712    /// other byte.
713    pub fn interleave_byte_blocks(separated: &mut [u8]) {
714        with_reused_buffer(separated.len(), |interleaved| {
715            // Split the two halves that we are going to interleave.
716            let (first_half, second_half) = separated.split_at((separated.len() + 1) / 2);
717            // The first half can be 1 byte longer than the second if the length of the
718            // input is odd, but the loop below only processes numbers in pairs.
719            // To handle it, preserve the last element of the first slice, to be handled
720            // after the loop.
721            let first_half_last = first_half.last();
722            // Truncate the first half to match the lenght of the second one; more
723            // optimizer-friendly
724            let first_half_iter = &first_half[..second_half.len()];
725
726            // Main loop that performs the interleaving
727            for ((first, second), interleaved) in
728                first_half_iter.iter().zip(second_half.iter()).zip(interleaved.chunks_exact_mut(2))
729            {
730                // The length of each chunk is known to be 2 at compile time,
731                // and each index is also a constant.
732                // This allows the compiler to remove the bounds checks.
733                interleaved[0] = *first;
734                interleaved[1] = *second;
735            }
736
737            // If the length of the slice was odd, restore the last element of the first
738            // half that we saved
739            if interleaved.len() % 2 == 1 {
740                if let Some(value) = first_half_last {
741                    // we can unwrap() here because we just checked that the lenght is non-zero:
742                    // `% 2 == 1` will fail for zero
743                    *interleaved.last_mut().unwrap() = *value;
744                }
745            }
746
747            // write out the results
748            separated.copy_from_slice(interleaved);
749        });
750    }
751
752    /// Separate the bytes such that the second half contains every other byte.
753    /// This performs deinterleaving - the inverse of interleaving.
754    pub fn separate_bytes_fragments(source: &mut [u8]) {
755        with_reused_buffer(source.len(), |separated| {
756            // Split the two halves that we are going to interleave.
757            let (first_half, second_half) = separated.split_at_mut((source.len() + 1) / 2);
758            // The first half can be 1 byte longer than the second if the length of the
759            // input is odd, but the loop below only processes numbers in pairs.
760            // To handle it, preserve the last element of the input, to be handled after the
761            // loop.
762            let last = source.last();
763            let first_half_iter = &mut first_half[..second_half.len()];
764
765            // Main loop that performs the deinterleaving
766            for ((first, second), interleaved) in
767                first_half_iter.iter_mut().zip(second_half.iter_mut()).zip(source.chunks_exact(2))
768            {
769                // The length of each chunk is known to be 2 at compile time,
770                // and each index is also a constant.
771                // This allows the compiler to remove the bounds checks.
772                *first = interleaved[0];
773                *second = interleaved[1];
774            }
775
776            // If the length of the slice was odd, restore the last element of the input
777            // that we saved
778            if source.len() % 2 == 1 {
779                if let Some(value) = last {
780                    // we can unwrap() here because we just checked that the lenght is non-zero:
781                    // `% 2 == 1` will fail for zero
782                    *first_half.last_mut().unwrap() = *value;
783                }
784            }
785
786            // write out the results
787            source.copy_from_slice(separated);
788        });
789    }
