# 03-testing.md — テスト戦略・観点

## 目的

単体テスト、結合テスト、リグレッションテスト、GUI スモークテスト、クロスプラットフォームテストを体系化し、品質を担保する。

## 単体テスト

`tests/test_*.py` として各 `core/` モジュールに対応するテストを作成する。

| 対象 | 観点 |
|------|------|
| `core/config.py` | デフォルト値補完、未知キー無視、deep merge、読み書き |
| `core/capture_profiles.py` | ビルトイン/カスタムプロファイルの保存/読み込み |
| `core/boundary_detector.py` | full/manual/auto 各方式の出力座標、異常画像での挙動 |
| `core/trimmer.py` | 4 辺トリミング後の画像サイズ、出力保存、進捗コールバック |
| `core/pdf_extractor.py` | PDF 展開、DPI 指定、PNG/JPG 出力、連番命名 |
| `core/ocr_preprocess.py` | アップスケール倍率、コントラスト調整、二値化閾値 |
| `core/text_replacements.py` | literal 置換、regex 置換、長いキー優先、壊れた JSON ハンドリング |
| `core/text_reflow.py` | 日本語結合、英語結合、ハイフン除去、構造行保護 |
| `core/chapter_detector.py` | 第 N 章 / Chapter N パターン、除外語句、レベル判定 |
| `core/pdf_builder.py` | 5 形式の PDF 生成、しおり生成、画像順序 |
| `core/markdown_writer.py` | フロントマター、ページ区切り、画像埋め込み有無 |
| `ui/state.py` | Observer パターン、複数リスナー、イベント伝播 |

## 結合テスト

- **キャプチャエンジン**: ウィンドウ操作をモック化し、差分判定・ページめくりエスカレーション・停止処理を検証
- **OCR パイプライン**: 前処理 → OCR → 置換 → 段落整形 → 章検出 → 出力生成の一連の流れ
- **タブ間連携**: `capture_complete` / `trim_complete` イベントが正しく次タブに反映されるか

## リグレッションテスト

| 落とし穴 | テスト内容 |
|---------|-----------|
| ウィンドウ誤検出 | `process_name` 指定時に該当プロセスがいない場合 `None` を返す |
| macOS 信号機ボタン誤操作 | `activate_window` が macOS でクリックを伴わない実装になっているか |
| 1px 差分による誤ページ判定 | 差分ピクセル比率が閾値未満の場合は「変化なし」と判定する |
| ページめくり失敗 | 既定キー無効時に space → pagedown → down → scroll の順にエスカレーションする |
| 画面ロック中の撮影継続 | 最前面でなくなったらキャプチャループが停止する |
| PyInstaller `sys.executable` 問題 | OCR サブプロセス起動時に実 Python パスを解決できる設計になっている |

## GUI スモークテスト

- アプリがクラッシュせず起動する
- 4 タブの切り替えが正常に動作する
- 各タブの主要ボタンが存在し、クリックで処理が開始/停止する（外部処理はモック可）

## パフォーマンス・負荷テスト

- 100 ページ以上の PDF 展開が途中で停止せず完了する
- 大きい画像（Retina 解像度）でもトリミング/OCR 前処理でメモリ不足にならない
- OCR 処理中も UI がフリーズせず、進捗が更新される

## クロスプラットフォームテスト

- Windows / macOS の両方で以下が同じように動作する
  - ウィンドウ検索・前面化
  - スクリーンショット取得（座標系の整合）
  - キー送信
  - 設定ファイルの読み書き
  - 出力 PDF / Markdown の文字化けなし

## テスト実行コマンド

```bash
ruff check .
ruff format --check .
pytest tests/ -q
```

## テスト作成の指針

- 外部 API やウィンドウ操作は可能な限りモック化する
- 画像処理のテストには小さなフィクスチャ画像を `tests/fixtures/` に配置する
- テスト名は `test_<対象>_<シナリオ>_<期待結果>` の形式を推奨
- 各 `core/` モジュールには `if __name__ == "__main__":` による簡易 CLI 動作確認も残す
