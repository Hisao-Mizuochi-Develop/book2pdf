# 11-pitfalls.md — 既知の落とし穴と回避策

このファイルは、過去のバージョンで実際に発生した不具合と、その回避策です。ゼロから実装する際、同じ不具合を再発させないよう、設計に最初から組み込んでください。

## 1. ウィンドウの誤検出

**症状**: 対象アプリが閉じている状態でキャプチャを実行すると、デスクトップや別のウィンドウが撮影され続ける。

**原因**: ウィンドウ検索が「タイトル部分一致」＋「プロセス名一致はスコア加点のみ」だったため、無関係なウィンドウを選んでしまっていた。

**回避策**:
- `process_name` が指定された場合、そのプロセス名のウィンドウが 1 件も見つからなければ `None` を返す
- タイトルのみのフォールバックは禁止

## 2. macOS でウィンドウが勝手にフルスクリーン化/消える

**症状**: キャプチャ開始直後、対象アプリがフルスクリーン Space に切り替わり、以後ウィンドウが見つからなくなる。

**原因**: 前面化後に「フォーカスを確実にするため」ウィンドウ左上付近をクリックしていた。macOS の信号機ボタン（閉じる/しまう/フルスクリーン）と重なって誤操作を起こしていた。

**回避策**:
- macOS では `NSRunningApplication.activateWithOptions_` によるアプリレベルのアクティブ化のみ使用
- ウィンドウ内をクリックする処理を実装しない
- どうしてもクリックが必要な場合は、左上 `x<100, y<60` を避ける

## 3. ページが変化しないのに「変化した」と誤検出

**症状**: ページがめくれていないのに、同一ページの画像が連番で量産される。

**原因**: 変化判定が「1 ピクセルでも異なれば変化」という厳格すぎる判定だったため、カーソルの点滅・時計表示等のノイズを「ページめくり」と誤検出していた。

**回避策**:
- 差分ピクセル数の全体に対する比率を計算
- 一定の閾値（目安 0.5%）を超えた場合のみ「変化した」とみなす

## 4. ページめくりキーが効かず、同じページを撮り続ける

**症状**: ページが進まないまま停止する、または同一ページを量産する。

**原因 A**: macOS でアクセシビリティ権限が無いと、合成キー入力が例外を出さずに黙って失敗する。

**原因 B**: そのアプリ/表示モードに既定のキーが効かない（連続スクロール表示等）。

**回避策**:
- キャプチャ開始前に権限をチェックし、無ければエラーメッセージを表示
- 既定キーで一定時間変化がなければ、自動的に別方式（space → pagedown → down → scroll）へエスカレーション
- 一度有効な方式が見つかったら、以降のページもその方式を使い続ける

## 5. Retina ディスプレイでの座標系のズレ（macOS）

**注意点**: `CGWindowListCopyWindowInfo` の座標はポイント単位、`ImageGrab.grab()` は bbox 指定の有無で出力解像度の意味合いが変わる。

**回避策**:
- `bbox` を指定した場合はポイント座標をそのまま渡す
- 全画面取得してから crop する方式に変更する場合は、必ずテストスクリプトでサイズを確認

## 6. 画面ロック中にキャプチャが継続

**症状**: 長時間キャプチャ中に画面ロックされても、ロック画面やデスクトップを撮り続ける。

**回避策**:
- キャプチャループの各イテレーションで「対象ウィンドウが現在最前面か」を確認
- 最前面でなくなれば安全に停止してエラー表示

## 7. NDLOCR-Lite をフリーズ環境で動かす場合の落とし穴

**注意点**: OCR 呼び出しコードが `sys.executable` を使ってサブプロセスを起動する場合、PyInstaller 等で凍結すると `sys.executable` がアプリ自身を指してしまい、サブプロセス起動が壊れる。

**回避策**:
- venv ベースの起動方式を基本とする
- 凍結時は実インタプリタのパスを別途保持する設計にする
- `core/ocr_engine.py` 内で Python 実行ファイルのパスを適切に解決する

## 8. config.json の破損・旧バージョン互換性

**症状**: 設定ファイルが壊れている、または旧バージョンのキーが残っているとアプリが起動しない。

**回避策**:
- `core/config.py` で deep merge を行い、未知のキーは無視
- 欠けているキーは `DEFAULT_CONFIG` で補完
- JSON パースエラー時はデフォルト値で起動
