# 08-pdf-load.md — PDF 読込・画像展開

## ゴール

既存 PDF を画像フォルダに展開し、キャプチャタブと同じく「画像フォルダを用意する」入力源として機能させる。

## ファイル構成

```
core/
└── pdf_extractor.py    # PDF → 画像展開
```

## 機能要件

### UI 項目

| 項目 | 説明 |
|------|------|
| PDF ファイル選択 | ファイルダイアログで選択 |
| 出力フォルダ | 未設定時は `<PDF名>_pages` を自動設定 |
| DPI | 150 / 200 / 300 / 400 から選択。OCR 目的なら 200〜300 |
| 形式 | PNG（無劣化）/ JPG（軽量） |

### 出力命名規則

展開後の画像は `001.png`, `002.png`, ... の連番で保存する。桁数はページ数に応じて自動調整する。

### 処理フロー

1. PDF ファイルを選択
2. 出力フォルダが未設定の場合、`<PDF名>_pages` を自動設定
3. `pypdfium2` で各ページをレンダリング
4. 指定形式・DPI で画像保存
5. 進捗を `on_progress(current, total, filename)` で通知
6. 完了後、`AppState` で `capture_complete` イベントを発行（画像フォルダパスを含める）

## エラーハンドリング

- PDF が破損している場合は `(False, "エラーメッセージ")` を返す
- 出力フォルダが存在しない場合は自動作成する
- 既存ファイルがあっても上書きする（確認ダイアログは UI 側で任意）

## UI 要件（pdf_load_tab.py）

- PDF ファイル選択ボタン
- 出力フォルダ入力＋選択ボタン
- DPI 選択ドロップダウン
- 形式選択（PNG / JPG）
- 実行ボタン
- 進捗ログ表示

## 完了条件

- PDF ファイルを選択すると出力フォルダが `<PDF名>_pages` に自動設定される
- DPI を変えて展開すると、画像サイズが期待通りスケールする
- 展開後、トリミングタブ・変換タブに画像フォルダが自動引き継がれる
