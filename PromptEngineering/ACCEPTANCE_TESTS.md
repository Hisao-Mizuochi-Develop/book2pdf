# ACCEPTANCE_TESTS.md — 完成判定チェックリスト

本アプリはGUI+実機自動操作が中心のため、コードレビューや静的解析だけでは
「動く」ことを保証できない。以下のチェックリストを**実機で実際に操作して**
確認すること。Claude Codeが自律的に実装を進める場合も、各セクション完了時に
可能な範囲でこのチェックを自己実行すること（実機がない場合は該当スクリプトを
提示し、ユーザーに実行結果の報告を求めること）。

## 前提確認

- [ ] `python --version` が3.11〜3.13の範囲内
- [ ] tkinterが利用可能（`python -c "import tkinter"` がエラーなく通る）
- [ ] （macOSのみ）`pyobjc-framework-Quartz` 等がインストール済み

## core/platform/ の疎通確認

以下のようなワンショットスクリプトで確認する（実装後に必ず実行）。

```python
from core.platform import find_window, get_window_rect, activate_window, is_window_frontmost

hwnd = find_window("kindle", process_name="Kindle.exe")  # 実際に起動しているアプリ名に置き換え
assert hwnd is not None, "対象ウィンドウが見つからない"

rect = get_window_rect(hwnd)
print("rect:", rect)  # (0,0,0,0)ではないこと

activate_window(hwnd)
assert is_window_frontmost(hwnd), "前面化に失敗している"
```

- [ ] 対象アプリが起動していない状態で `find_window(..., process_name=...)` を
      呼ぶと `None` が返る（無関係なウィンドウを誤って返さない）
- [ ] 対象アプリを起動した状態で `find_window()` が正しいウィンドウを検出する
- [ ] `activate_window()` 実行後、対象アプリのウィンドウ状態が変化していない
      （フルスクリーン化していない、最小化していない、閉じていない）
- [ ] `get_window_rect()` の座標をそのままスクリーンショットのbboxに渡すと、
      実際に対象ウィンドウの中身（デスクトップや他ウィンドウではなく）が写る

## キャプチャ機能の実機確認

- [ ] 電子書籍アプリで本を開き、最初のページを表示した状態でキャプチャを開始すると、
      1ページ目が正しく保存される
- [ ] ページめくり後、2ページ目以降の画像が**内容の異なる**連番ファイルとして
      保存される（生成された画像を目視し、ページ番号や内容が実際に進行しているか確認する。
      同一内容の画像が連番で量産されていないか必ず確認する）
- [ ] 最後のページに到達すると自動停止し、正しい合計ページ数が報告される
- [ ] 「停止」ボタンで安全に中断できる
- [ ] キャプチャ中に対象ウィンドウを最前面から外す（別ウィンドウをクリックする）と、
      安全に停止しエラーメッセージが表示される（デスクトップ等を撮り続けない）
- [ ] （権限確認できる環境で）画面収録/アクセシビリティ権限が無い状態で実行すると、
      明確なエラーメッセージが表示され、無意味な画像を生成しない

### ページめくりエスカレーションの確認

意図的に無効なページめくりキー（存在しないキー名など）をプロファイルに設定し、
以下を確認する。

- [ ] 一定時間後、自動的に別の方式（スペースキー等）にエスカレーションする
- [ ] エスカレーション後、複数ページ連続して正しく撮影が進行する
- [ ] ログ/ステータス表示に「別の方式を試します」等の案内が出る

## PDF読込タブ

- [ ] PDFファイルを選択すると、出力フォルダが `<PDF名>_pages` に自動設定される
- [ ] DPIを変えて展開すると、画像サイズが期待通りスケールする
- [ ] 展開後、次タブ（トリミング/変換）に出力フォルダが自動引き継ぎされる

## トリミングタブ

- [ ] 「自動検出」ボタンで4辺の余白が概算され、余裕を持たせた値になっている
      （検出値ぴったりではなく、コンテンツを切り落とさない方向に安全マージンがある）
- [ ] プレビューのbefore/afterが実際のトリミング結果と一致する
- [ ] 「トリミング実行」で全画像が一括処理され、出力フォルダに保存される
- [ ] 「デフォルトとして保存」で設定した値が、アプリ再起動後も引き継がれる

## 変換タブ — 5形式すべてで確認

任意のキャプチャ済み画像フォルダ（3〜6ページ程度）を用意し、各形式で
変換を実行して以下を確認する。

- [ ] **画像PDF**: OCRなしで即座に生成され、全ページの画像が正しい順序で含まれる
- [ ] **テキストPDF**: OCRが実行され、抽出テキストが読める形でPDF化される。
      1ページのテキストが長い場合、自動的に複数PDFページへ折り返される
- [ ] **検索可能PDF**: 見た目は画像PDFと同一だが、PDFビューアでテキスト検索
      （Cmd/Ctrl+F）すると本文がヒットする
- [ ] **Markdown**: `.md` ファイルが生成され、ページ区切りとフロントマターが
      含まれる。「ページ画像を併記」を有効にすると画像へのリンクも本文に含まれる
- [ ] **画像+テキストPDF**: 「画像ページ→同じページのテキストページ」の順序が
      全ページ分正しく繰り返されている（PDFを実際に開いてページ順を目視確認する）

### 共通オプションの確認

- [ ] OCR前処理（アップスケール・コントラスト強調）の有無で、OCR結果の
      精度に体感できる差が出る（低解像度画像でテスト）
- [ ] 置換辞書（`replacements.json`）にルールを追加すると、OCR結果に反映される
- [ ] 章自動検出が有効な場合、PDFのしおりパネル/Markdownの見出しに
      検出された章タイトルが表示される
- [ ] 「段落を自動整形」を有効にすると、OCRの改行ノイズが結合され読みやすくなる

## 設定の永続化

- [ ] アプリを再起動しても、前回保存した設定（トリミング余白・カスタム
      プロファイル・OCRオプション等）が復元される
- [ ] `config.json` を手動で削除しても、デフォルト値でエラーなく起動する
- [ ] 未知のキーを含む `config.json`（旧バージョン等）を読み込んでも
      エラーにならない
